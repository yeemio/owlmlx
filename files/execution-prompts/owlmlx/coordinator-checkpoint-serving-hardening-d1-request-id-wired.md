# owlmlx Coordinator Checkpoint — Serving Hardening D-1 Request-id Wired

## Verdict

- `serving_hardening_d1_request_id_middleware_wired_lossless`

The D-1 wiring round is closed. The C-4 scaffold's
`RequestIdMiddleware` is now installed on the real owlmlx FastAPI app
constructed by `owlmlx.runtime.server.create_app(...)`. The
middleware honors its lossless contract: an inbound `x-request-id`
header is preserved verbatim, an absent inbound header causes a fresh
`req_<uuid4hex>` to be generated, and the outbound response always
carries the header — including on 404 paths and on routes that do
not write their own `x-request-id`.

The remaining five C-4 hardening primitives (timeout, graceful
shutdown drain, error envelope, metrics exporter, idempotent
`/v1/load`) are NOT wired in this round; each is a separate operator
decision in its own future D-* round.

## Notable Implementation Choices

- **Import style**: relative import
  `from .serving_hardening import RequestIdMiddleware` mirrors the
  existing relative-import block (`from .backends`, `from .kernel`,
  `from .types`). Top-of-file rather than local-to-call so that the
  import cost is paid once at module load, not per `create_app(...)`
  invocation.
- **Placement of `app.add_middleware(...)`**: immediately after the
  `app = FastAPI(...)` line and before any `app.state.*` assignment.
  Starlette's middleware stack must be constructed before the first
  request is dispatched; adding it before `app.state.*` is also a
  cleaner read-order for the file.
- **`/healthz` as the primary test surface**: the route requires no
  loaded backend and returns a stable JSON body, so the middleware's
  body-invariance can be asserted by direct equality of two
  `response.json()` payloads.
- **Lossless contract verified via the per-route precedence**: the
  middleware's `dispatch()` reads
  `if REQUEST_ID_HEADER not in response.headers` before writing.
  Routes that already write `x-request-id` (the five OpenAI/Anthropic
  routes) keep their handler-generated id. Routes that do not (every
  other route, including `/healthz`, runtime-status routes, and 404
  paths) get the middleware-generated id.
